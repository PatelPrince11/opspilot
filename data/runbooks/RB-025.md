# Reference card: the edge's public certificate

## What it is

The certificate edge-gateway presents on port 443 to every client. A public CA issues it. It is stored in the Secret `edge-public-tls` (namespace `platform`) and mounted into each edge pod as files. Envoy reads those files when it starts, so a renewed Secret takes effect only after `kubectl -n platform rollout restart deploy/edge-gateway`.

| Item | Value |
|---|---|
| Validated by | Clients: browsers, mobile apps, partner integrations |
| Loaded on | edge-gateway-01, -02 and -03, each pod on its own |
| Restart behaviour | 3 pods; surge 1, unavailable 0: one new pod at a time, three serving throughout |
| Renewal | team-platform, 30 days before expiry |
| Watch | an outside probe checks the expiry date daily |

## What an expired certificate looks like from inside

Clients abandon the handshake before sending any HTTP. Envoy never sees a request, so:

- nothing in the access log, so no response flag and no 5xx
- request rates fall across all routes at the same moment
- successful handshakes (`listener.<address>.ssl.handshake`) drop off with them
- `listener.<address>.ssl.connection_error` (TLS errors other than failed certificate verification) is worth watching, but Envoy's docs don't say whether a client rejecting our certificate is counted there

Envoy's admin listener (9901) is reachable only inside each pod. Forward it from one pod at a time:

```
kubectl port-forward -n platform <edge-gateway pod name> 9901
curl -s http://127.0.0.1:9901/stats | grep -E 'ssl\.(handshake|connection_error)'
```

## What clients actually receive

```
openssl s_client -connect edge-gateway-02.prod.internal:443 -servername <public hostname> </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -enddate
```

Run it against all three pods. A pod that missed its restart keeps serving the old certificate. Always pass `-servername`: without SNI, Envoy may answer from a different filter chain.

## Four failures that all look like "the certificate"

| Problem | `openssl s_client` (verify result) | Fix |
|---|---|---|
| Leaf expired | `Verify return code: 10 (certificate has expired)`; leaf `notAfter` in the past | Renew, update the Secret, restart |
| Intermediate missing from the file | `Verify return code: 21 (unable to verify the first certificate)` | Put leaf then intermediate in the certificate file |
| Intermediate expired | Code 10, but `-showcerts` shows the expired date on the intermediate | Fetch the CA's current chain |
| Client clock wrong | One client fails, everyone else fine | Client side; nothing to change at the edge |

## Done when

All three pods serve the new `notAfter`, request rates are back to their usual shape for an hour, and `ssl.handshake` climbs at its normal pace.
