# A feature-store restart and the minutes it spent loading, 2026-01-25

risk timeline, sev4, 01:50 to 02:00 UTC. Reference card: RB-019.

```
01:50  redis-features-01 restarts and starts reading its dataset from disk
01:50  it replies LOADING to commands that arrive during the read
01:50  fraud-scorer-01 starts logging FRD-W118 for feature lookups it cannot get answered
02:00  loading complete; LOADING replies stop and FRD-W118 ends
```

## What kind of event this was

redis-features-01 is a single node with no standby, so any restart of it leaves a gap. A restarted Redis does not serve data until its snapshot is back in memory, and during that stretch it answers commands with `LOADING` instead of values. That is what the scorer's side saw: not a refusal and not a dead server, only a node that was not ready yet.

The cause of the restart was not recorded. Whether it was planned, manual or a crash is not known.

## What fraud-scorer-01 did

fraud-scorer-01 logged `FRD-W118`, the warning fraud-scorer writes when redis-features is slow to give it features. Lines per minute and the effect on scoring results during the load were not recorded.

The reference card for redis-features, RB-019, is written for refused writes, which is a different state from a node that is loading. This episode did not match its main case.

## Length

The lookups affected were those fraud-scorer-01 sent to redis-features-01 between 01:50 and 02:00.

The whole episode ran 10 minutes, from the restart at 01:50 to the end of the loading at 02:00. It was sev4. No change to any setting is recorded.
