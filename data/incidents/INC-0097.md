## Why it reached the limit this time

The memory budget is tight. `WEB_CONCURRENCY` is unset, so the pod runs one worker per visible core: 16 on its node. At about 150 MiB per warm worker that is 2,400 MiB before any cache growth, inside a 3,072 MiB limit. That leaves 672 MiB for the feature cache, and each slow stretch on redis-features filled it. The memory panel shows the same shape both times: level, then a straight climb from the first spikes to the kill.
