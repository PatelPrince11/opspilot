# A pool-size change that did not fit the database

sev2 · 2026-04-21 · 10:05 to 10:40 UTC · cause: bad deploy · affected: inventory-db · runbook: RB-012

| Host or team | UTC | What happened |
|---|---|---|
| inventory-service-01, inventory-service-02 | 10:05 | A release of inventory-service went out with the connection pool per pod changed from 20 to 80. The pods began opening more connections to inventory-db-01 than before. |
| inventory-db-01 | 10:05 | Once the application role had used up the slots open to it, new connection attempts were refused with SQLSTATE `53300`. |
| inventory-service-01, inventory-service-02 | 10:05 | The pods saw failed connection attempts rather than slow queries, which is the mark of this class of error. |
| on-call | 10:05 to 10:40 | Compared the pools with the database's budget (below) and followed RB-012's first lever. |
| inventory-service | 10:40 | Release rolled back; pools back at 20 per pod. |
| inventory-db-01 | 10:40 | New connections accepted. Closed. |

## The numbers behind the refusals

| Quantity | Value |
|---|---|
| max_connections on inventory-db-01 | 100 |
| Held back, outside the application's reach | 3 |
| Left for inventory-service | 100 - 3 = 97 |
| Pool before the release, two pods | 2 x 20 = 40 |
| Pool after the release, two pods | 2 x 80 = 160 |
| Wanted beyond what exists | 160 - 97 = 63 |

The old pools asked for 40 of the 97. The new ones asked for 63 more than exist, so the surplus could never succeed. The release changed one number in one service; the database saw it multiplied by two pods.

## What was decided

The rollback of the release was chosen over any change to the database. The setting on inventory-db-01 itself would have needed a restart of the server and a decision by team-dba, while undoing the release removed the demand on its own. After the rollback each pod was back to a pool of 20, and the refusals were gone by 10:40.

## Afterwards

- Check a pool-size change against the database's slot count for all pods at once, before it ships.
- Put the per-database slot figures where the release reviewer will see them.
