# Growing template cache: notification-worker-01 killed for memory

sev4 · 2025-01-18 23:40 to 2025-01-19 00:40 UTC · cause: notification-worker · affected: notification-worker-01 · runbook: RB-005

| Time (UTC) | Component | Entry |
|---|---|---|
| 23:40 | notification-worker-01 | Container terminated with `OOMKilled` and restarted. Memory in the new process started low and began to rise again. |
| during the hour | notification-worker-01 | The container was killed again; the times and the number of kills were not kept. |
| 00:40 | notification-worker-01 | No further `OOMKilled`. Incident closed. |

## Cause

The cause was an in-process cache of message templates inside the worker. It grew without a limit, and when the process had taken more memory than the container is allowed, the kernel killed the container. Because the cache lives inside the process, each kill emptied it, which is why a restarted worker began with memory low and then climbed again. That climb-then-kill pattern is the one RB-005 contrasts with a limit that is simply too small for a known peak.

## Effect

The incident is sev4. The worker sends emails through an external provider. How much mail was delayed while the container was cycling was not recorded, and no measure of any queue behind it was kept. The hour from 23:40 to 00:40 is 60 minutes.

## Where it happened

Only notification-worker-01 is named. Its container is the one with the cache, and the kills and restarts happened on that pod. The worker consumes the `notification-worker` group's messages and sends through the provider's HTTP API, so each restart paused that work until the new process came up.

## In-flight work

The worker has up to 20 sends in flight per pod. A kill ends the process with whatever sends were in progress at that moment, and the outcome of those sends is not recorded. Since the number of kills was not kept either, the number of sends affected cannot be estimated from what remains.

## Suggestions

- Give the template cache a size bound or an expiry, so memory flattens instead of climbing.
- Look at the memory history for the worker when it restarts without an obvious job behind it.
