# redis-features-01 write refusals, 26 April 2026

sev3, 18:10 to 19:15 UTC. Runbook: RB-019.

**What broke.** From 18:10 fraud-scorer-01 and fraud-scorer-02 logged `FRD-E140`: their velocity-counter writes came back with `OOM command not allowed`. Scoring went on, but per-card counters stopped updating.

**Why.** `INFO memory` on redis-features-01 showed used memory at `maxmemory 24gb` with `noeviction`, so Redis refused writes and served reads. The last background save was fine, which pointed to memory rather than snapshots.

**Fix.** A `--memkeys` sample at 18:35 showed where the memory sat. team-risk was paged before anything was deleted and picked keys to remove at 18:58. Used memory fell below the cap at 19:10. The probe `INCR` succeeded, `FRD-E140` stopped, and the incident closed at 19:15.

**Open.** An alert well before the cap.
